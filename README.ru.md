# Neural Notes

Статический интерактивный учебник на русском и английском по восьми приложенным расшифровкам курса Андрея Карпати **Neural Networks: Zero to Hero**. Сохраняет последовательность лекций: от скалярной производной до GPT и токенизации.

[English](README.md) · [Полная карта курса и источников](docs/COURSE_MAP.md) · [Результаты проверок](docs/VALIDATION.md)

## Локальный запуск

Нужны **Node.js 24** и npm. Для работы сайта не нужны API keys, backend, Python или скачивание моделей.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Production-версия:

```sh
npm run build
npm run preview
```

Папку `dist/` нужно раздавать по HTTP(S), а не открывать через `file://`. Скрипты, стили, математические шрифты, учебные тексты и расшифровки входят в локальную сборку. Основная функциональность не обращается к внешним API или CDN.

## Что реализовано

32 урока: по четыре на каждую лекцию.

1. **Micrograd**: производные, вычислительные графы, автоматический backward, обучение.
2. **Биграммная модель**: счётчики, выборка и broadcasting, NLL и сглаживание, нейросетевая формулировка.
3. **MLP**: окна контекста, embeddings, устойчивая оптимизация, разделение данных.
4. **Активации и BatchNorm**: инициализация, насыщение, нормализация, диагностика.
5. **Ручной backprop**: тензорные производные, поправка дисперсии, backward cross-entropy и BatchNorm.
6. **Иерархия по мотивам WaveNet**: модули, попарное объединение, оси нормализации, эксперименты.
7. **GPT**: targets следующего токена, causal attention, Transformer-блоки, генерация и границы предобучения.
8. **Токенизация**: Unicode/UTF-8, обучение BPE, encode/decode, специальные токены и словарь.

В каждом уроке: простое и техническое объяснения, формула с расшифровкой обозначений, запускаемый пример Python, разбор кода, частые ошибки, блок «Подробнее», резюме, проверка знаний и практика из восьми пунктов со скрытыми подсказкой и решением.

Восемь лабораторий показывают касательную и производную, сглаживание биграммы, lookup embedding, насыщение tanh, градиент cross-entropy, иерархическое объединение, causal attention и byte-level BPE. Это учебные симуляции, а не обученные языковые модели. Python-код выполняется отдельно от сайта; примерам с `import torch` нужен PyTorch.

## Источники и авторские дополнения

- `sources/0.txt` — приложенный обзор курса. Реклама и элементы каталога не перенесены в уроки.
- `sources/1.txt`–`sources/8.txt` — сохранённые исходные расшифровки. SHA-256 и диапазоны глав приведены в `docs/COURSE_MAP.md`.
- `src/data/curriculum.js` хранит последовательность и точные таймкоды. `relatedChapters` фиксирует обращения к главам вне основного диапазона урока.
- `src/data/sources.json` содержит все распознанные реплики. Он загружается только при открытии блока оригинальной расшифровки. Исходные английские субтитры явно подписаны и оставлены на языке оригинала; весь учебный текст и интерфейс переведены полностью.
- Основные объяснения — **редакционный пересказ**, а не цитаты, приписанные Карпати. Ошибки распознавания вроде «bathroom» вместо BatchNorm исправлены в учебном тексте, но не в оригиналах.
- Оформление формул и обозначений, короткие численные примеры и Python-код, восемь визуальных лабораторий, 32 проверки, пошаговая практика и поясняющие отступления снабжены плашкой **«Дополнительное объяснение»** рядом с материалом. Математические идеи следуют лекциям; упражнения и их оформление созданы для сайта.
- Раздел WaveNet показывает учебную иерархию, а не всю исходную архитектуру. RNN/LSTM/GRU упомянуты как будущие направления, а не вымышленные пройденные лекции. RLHF, сжатие промптов и мультимодальная токенизация даны в пределах исходного обзора. Упоминания версий продуктов относятся ко времени записи.

Повторное построение индекса субтитров:

```sh
node scripts/ingest-sources.mjs
npm run docs:map
```

Можно передать другой каталог: `node scripts/ingest-sources.mjs /path/to/transcripts`. Ожидаются файлы `0.txt`–`8.txt`. Команда выводит последовательную выборку глав для анализа. Учебные тексты и переводы редактируются вручную; повторная индексация их не перезаписывает.

```text
├── index.html
├── package.json / package-lock.json
├── vite.config.js
├── eslint.config.js / .prettierrc.json
├── playwright.config.js
├── .github/workflows/pages.yml
├── public/
│   ├── favicon.svg
│   └── licenses/
├── sources/                    # Оригиналы 0–8
├── scripts/
│   ├── ingest-sources.mjs       # Таймкоды и контрольные суммы
│   ├── course-map.mjs           # Карта курса и источников
│   ├── check-examples.mjs       # Запуск показанного Python-кода
│   └── serve-dist.mjs           # Статический сервер проверок /course/
├── src/
│   ├── main.js                 # Каркас, hash-навигация, жизненный цикл
│   ├── components/             # Лаборатории и пять типов проверок
│   ├── pages/                  # Урок и карта курса
│   ├── content/
│   │   ├── ru/                 # Восемь модулей русского контента
│   │   ├── en/                 # Восемь модулей английского контента
│   │   ├── ru.js / en.js        # Точки входа языков
│   │   └── examples.js          # Общий код, TeX, эталонные ответы
│   ├── i18n/                   # Отдельные тексты интерфейса RU/EN
│   ├── data/                   # Программа, диапазоны, субтитры
│   ├── styles/                 # Tokens, layout, content, labs; BEM
│   ├── utils/                  # Экранирование, математика/BPE, storage
│   └── tests/                  # Vitest и Playwright
└── docs/                       # Карта, проверки, скриншоты
```

Без runtime-фреймворка. Отдельно находятся каркас приложения, два шаблона страниц, компоненты заданий и лабораторий, контент и чистые функции. Hash-ссылки вроде `#/gpt/attention` не требуют серверного rewrite и работают после перезагрузки в подпапке репозитория.

Ключ localStorage `neural-notes:v1` хранит язык, тему, завершённые уроки, отправленные ответы и состояние лабораторий. При заблокированном или повреждённом хранилище сайт продолжает работать в памяти. Прогресс отмечает читатель; отправка ответа сама по себе не завершает урок.

## Как добавить тему

1. Впишите стабильный ID и таймкод в нужный модуль `src/data/curriculum.js`.
2. Добавьте одинаково структурированные записи в `src/content/ru/<module>.js` и `src/content/en/<module>.js`. Заполните все объяснения, обозначения и пункты практики.
3. Добавьте `formula`, `code` и спецификацию проверки в `src/content/examples.js`.
4. Укажите дополнительные главы в `relatedChapters`, если нужны. Отделяйте подтверждённые источником утверждения от авторских дополнений.
5. Если изменилось число уроков, обновите фиксированные итоговые значения в каркасе, тестах и документации. Текущая версия намеренно рассчитана на 8×4 урока.
6. Выполните `npm run docs:map`, форматирование и проверки.

## Как добавить quiz

Поле `quiz.type` поддерживает:

- `choice` — один правильный индекс варианта;
- `fix` — выбор исправления ошибки в коде;
- `number` — численный ответ с явной погрешностью; принимается десятичная запятая;
- `order` — массив индексов в нужном порядке, вводимый доступными с клавиатуры списками;
- `match` — индексы вариантов для локализованных `items`.

Вопросы, варианты, объяснение результата и элементы сопоставления находятся в RU/EN-записях урока. Эталонные ответы общие и хранятся в `examples.js`. Неверный ответ не завершает урок. Для новой математической логики добавьте проверку с независимо рассчитанным результатом.

## Формулы, графики и диаграммы

- Формула записывается в `formula` через `String.raw`. KaTeX создаёт HTML и MathML. Переведите расшифровку **каждого** обозначения в `symbols`. Контейнер формулы доступен с клавиатуры и прокручивается на узких экранах.
- Графики используют нативный SVG с `viewBox`, ограничением области кривых, HTML-подписями шкал и численным результатом. Вычисления размещаются в `src/utils/math.js`, отображение — в `src/components/labs.js`.
- Диаграммы иерархии и внимания построены адаптивным HTML; матрица внимания имеет ARIA-семантику таблицы. Подписи добавляются в оба файла `src/i18n/`.
- Дополнительные примеры нужно явно маркировать. Проверяйте единицы, оси, суммы softmax, формы и граничные случаи.

Chart.js, Plotly и Mermaid для этих небольших взаимодействий не нужны: нативные элементы позволяют обойтись без лишних зависимостей.

## Темы и доступность

`src/styles/tokens.css` задаёт **Dark**, **Light** и **Light Coffee** через CSS custom properties. Компоненты используют токены вместо повторения цветов. Атрибут `data-theme` на `<html>` переключает оформление; сохранённая тема восстанавливается до рендера.

CSS разделён по ответственности и именуется по BEM. На узких экранах оглавление раскрывается кнопкой; закрытая панель исключается из клавиатурной навигации через inert. Реализованы native controls/details, видимый фокус, skip-link, статусные сообщения, `prefers-reduced-motion`, локальная прокрутка кода и формул, адаптивные графики. Зафиксированы только верхняя панель и оглавление; учебный материал находится в обычном потоке.

## Использованные библиотеки

В браузере:

- **KaTeX** — формулы и локальные математические шрифты.
- **highlight.js** — подсветка Python; импортируются только ядро и нужная грамматика.

При разработке:

- **Vite** — локальный сервер и статическая сборка с относительными путями.
- **Vitest** — полнота контента, целостность источников, численные проверки и localStorage.
- **Playwright** — проверка production-сборки в Chromium.
- **ESLint**, **@eslint/js**, **globals** — lint JavaScript.
- **Prettier** — единое форматирование.

Точные версии фиксирует `package-lock.json`. Лицензии runtime-библиотек сохранены в `public/licenses/`. Внешних шрифтов, UI-фреймворка, аналитики и секретных ключей нет.

## Проверка качества

```sh
npx playwright install chromium
npm run format:check
npm run check
```

`check` запускает lint, unit-тесты, production build и e2e. Тесты намеренно раздают сборку из `/course/`, проверяют все 32 урока на двух языках, ответы всех типов, ширины 320/375/768/1024/1440/1920/2560, темы, хранение настроек, accordion, Copy, клавиатуру и лаборатории. Проверяется загрузка исходников без обращений к внешним ресурсам. Трассы сбоев сохраняются в `test-results/`, HTML-отчёт — в `playwright-report/`.

Дополнительная проверка Python-примеров требует Python 3 и PyTorch в выбранном окружении:

```sh
python -m pip install torch
npm run test:examples
# Можно явно передать интерпретатор из отдельного окружения:
npm run test:examples -- /path/to/venv/bin/python
```

Python нужен только для обучения и проверки примеров, не для сайта. Проверка выполняет все показанные примеры, сверяет известные результаты и выполняет встроенные assertions. Фактические результаты и ограничения перечислены в `docs/VALIDATION.md`.

## Публикация на GitHub Pages

1. Создайте репозиторий GitHub и загрузите проект, исключив игнорируемые папки. Сохраните `package-lock.json`, исходные `sources/` и сгенерированный `src/data/sources.json`.
2. Используйте ветку **main** либо измените фильтр ветки в workflow.
3. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
4. Отправьте изменения в `main` либо вручную запустите **Check and deploy to GitHub Pages** во вкладке Actions.
5. Workflow установит зависимости и Chromium, проверит форматирование/lint/tests, соберёт `dist/` и опубликует только после успешных проверок.

Адрес: `https://<account>.github.io/<repository>/`. Настройка `base: './'` и hash-навигация поддерживают любое имя репозитория без прописанного hostname. Pull requests запускают проверки, но не публикацию. Собственный домен также не требует менять пути ресурсов. Проект подготовлен к публикации; репозиторий в вашем аккаунте автоматически не создавался.
